# Feature Specification: 管理员账号名登录

**Feature Branch**: `014-admin-username-login`

**Created**: 2026-10-26

**Status**: Implemented

**Input**: 用户要求把生产与测试管理员账号改为非邮箱账号，并使用指定密码登录。

## User Scenarios & Testing

### User Story 1 - 管理员使用账号名登录 (Priority: P1)

管理员在登录页输入账号名和密码，通过图形验证码后进入后台。

**Acceptance Scenarios**:

1. **Given** 管理员账号为 `a115846`，**When** 使用正确密码登录，
   **Then** 登录成功并返回管理员身份。
2. **Given** 登录模式，**When** 查看账号输入框，**Then** 允许输入邮箱或普通账号名。
3. **Given** 注册或找回密码模式，**When** 输入账号，**Then** 仍要求标准邮箱格式。
4. **Given** 空库首次部署，**When** 引导非邮箱管理员，**Then** 能正常创建账号且不因缺少 `@` 报错。

### Edge Cases

- 已有邮箱管理员改为普通账号名后，旧会话通过递增会话版本立即失效。
- 密码只保存 BCrypt 哈希；明文只允许出现在权限 600 的服务器环境文件和本地忽略配置。
- 普通用户邮箱登录行为保持不变。

## Requirements

- **FR-001**: 登录页 MUST 在登录模式允许“邮箱或账号”，注册与找回密码仍使用邮箱输入。
- **FR-002**: 登录接口 MUST 接受非邮箱账号名，错误提示统一为“账号或密码错误”。
- **FR-003**: 管理员引导 MUST 支持非邮箱账号名。
- **FR-004**: 管理员账号变更 MUST 递增会话版本，使旧登录失效。
- **FR-005**: 真实密码 MUST NOT 写入 Git 仓库。

## Success Criteria

- **SC-001**: 生产环境使用新账号和密码可完成真实登录，并取得 `ADMIN` 身份。
- **SC-002**: 自动化覆盖普通账号名引导和前端登录/注册输入类型差异。
- **SC-003**: 测试环境数据库账号、角色、状态与 BCrypt 密码校验通过。
- **SC-004**: 后端全量测试、前端构建和相关 E2E 通过。

## Assumptions

- “生产和测试的管理员账号密码”是指生产数据库和生产服务器所对应的本地测试开发库。
- 管理员账号名不要求包含 `@`，普通用户注册仍只允许邮箱。
