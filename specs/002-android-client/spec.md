# Feature Specification: 拾题安卓客户端（以网页端为准）

**Feature Branch**: `002-android-client`

**Created**: 2026-10-16

**Status**: Draft

**Input**: 用户要求 —— 「按照 SDD 流程开发安卓端，注意要以网页端为准，你新开一个文件夹」

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 登录后在手机上刷题 (Priority: P1)

备考的考生在地铁上打开 App，用现有账号登录，接着上次没做完的题目继续刷：
选择题立刻出对错，简答题提交后由 AI 判分并给意见，看不懂的题可以点 AI 解析。

**Why this priority**：刷题是这个产品的全部价值，也是用户在手机上最高频的动作。

**Independent Test**：用测试账号登录 → 选一个公共题库 → 答一道选择题 → 答一道简答题 →
退出应用再进入，确认停在上次未答的题目上。

**Acceptance Scenarios**：

1. **Given** 已注册账号，**When** 输入邮箱、密码与图形验证码登录，**Then** 进入首页并显示该账号的邮箱。
2. **Given** 已登录，**When** 选公共题库里的一个单元开始刷题，**Then** 题目按网页端同样的顺序出现。
3. **Given** 在一道选择题上选了错误选项，**When** 提交，**Then** 立即显示对错、正确选项标绿、错选标红，与网页端一致。
4. **Given** 在一道简答题上作答，**When** 提交，**Then** 显示 AI 判分结果与意见，并扣除与网页端相同的点数。
5. **Given** 已答完 3 道题，**When** 杀掉应用重新进入同一单元，**Then** 从第 4 道（上次未答的那道）继续。
6. **Given** 一道题的解析已生成过，**When** 再次点 AI 解析，**Then** 直接显示已缓存解析，不重复扣点。

---

### User Story 2 - 新用户注册与找回密码 (Priority: P1)

没有账号的用户在 App 里注册：填邮箱 → 收邮箱验证码 → 设密码 → 直接进入。
忘记密码时也能在 App 内收验证码重置，不必去网页端。

**Why this priority**：不能注册/找回的客户端会把新用户直接挡在门外。

**Independent Test**：用新邮箱完成一次注册；再用该邮箱走一次找回密码并重新登录。

**Acceptance Scenarios**：

1. **Given** 未注册邮箱，**When** 点击发送邮箱验证码，**Then** 出现 60 秒倒计时，同一邮箱一分钟内不能重复发送。
2. **Given** 邮箱验证码正确，**When** 提交注册，**Then** 注册成功并直接进入已登录状态。
3. **Given** 忘记密码，**When** 走「找回密码」流程（邮箱验证码 + 新密码），**Then** 能用新密码登录。
4. **Given** 登录页，**When** 不填图形验证码直接登录，**Then** 提示与网页端一致，注册与找回密码页不要求图形验证码。

---

### User Story 3 - 错题本与学习统计 (Priority: P2)

用户想复盘做错的题，并看到自己的累计正确率、做题量。

**Why this priority**：复盘是留存的关键动作，但依赖 P1 的刷题数据，所以排在刷题之后。

**Independent Test**：制造一道错题 → 打开错题本能看到它 → 打开统计页看到正确的做题量与正确率。

**Acceptance Scenarios**：

1. **Given** 有答错的题目，**When** 打开错题本，**Then** 列出这些题目及答错次数，与网页端同字段。
   （实现期修正：接口按题目去重、只保留最近一次作答，因此展示的是"这道题最近一次答错"，
   没有"答错次数"字段；同一道题不会重复出现，最近一次答对就自动移出。）
2. **Given** 有过作答记录，**When** 打开统计页，**Then** 显示累计做题量、正确率，数值与网页端一致。
3. **Given** 错题本里有题，**When** 打开错题本，**Then** 每条都显示题干、判定结果、所属题库与单元
   （与网页端展示的字段一致；接口不下发正确答案，网页端也不显示，安卓端不额外造。
   实现期核对：`GET /api/wrong-book` 只返回 record 视图，见 contracts §4）。
4. **Given** 错题本里有多道题，**When** 按题库或按判定（错误 / 部分正确）筛选，**Then** 列表与
   计数同步收敛，两个条件可叠加；筛选在客户端完成，不额外打接口（与网页端同一套条件）。
5. **Given** 错题本里筛出了一批题，**When** 点「练这批错题」（或点某一条只练那一道），
   **Then** 直接进入练习：题目顺序与错题本一致（最近错的排前面），从第一题开始、不做续做跳过；
   这一轮里答对的题回来后**自动从错题本消失**（服务端按最近一次作答判定）。

### User Story 4 - 查看点数与套餐，购买走网页 (Priority: P3)

用户想知道自己还剩多少点、当前是什么套餐；想充值时跳到网页端同一支付入口完成。

**Why this priority**：点数影响能否继续用 AI，但充值不是高频动作，且支付链路已有现成实现。

**Independent Test**：打开「点数与套餐」页，核对余额与套餐名与网页端一致；点充值能打开与网页端相同的支付页面。

**Acceptance Scenarios**：

1. **Given** 已登录且有余额，**When** 打开点数页，**Then** 显示余额、套餐名与流水记录要点。
2. **Given** 在点数页，**When** 点某个点数包，**Then** 用系统浏览器打开与网页端同一个支付地址。

---

### Edge Cases

- 会话过期：任何请求返回 401 时回到登录页，并保留"请先登录"的提示，不能停在空白页。
- 无网络 / 弱网：给出可重试的提示，不把上一次的数据当成本次结果。
- 图形验证码过期：提示文案与网页端一致（统一为"验证码错误或已过期"），并提供刷新图片。
- 游客（未登录）状态：可以浏览公共题库列表；点刷题/错题本/我的时引导登录，与网页端一致。
- 点数不足：AI 解析/判分被拒时，原样显示服务端提示（例如点数不足），不得吞掉。
- 后端返回 5xx：显示服务端 message，不显示堆栈、不泄露内部细节。
- 自建题库：未登录或非本人一律不可见（与网页端收录边界一致）。

### User Story 5 - 在手机上维护自己的题库（Priority: P2）

用户导入或手工建的题库，需要随手改：加单元、改题目、把过时的题下架、删掉不要的题库。
这些能力网页端都有，安卓端要对齐，而不是只在网页端能改。

**Independent Test**：新建一个空题库 → 建两个单元 → 新增一道选择题和一道简答题 →
改题干 → 把题目下架 → 删掉单元 → 用邮箱验证码删掉整个题库，全程不碰网页端。

**Acceptance Scenarios**：

1. **Given** 已登录且名下有题库，**When** 打开「题库管理」，**Then** 只列出我有维护权的题库（管理员额外能看到公共题库）。
2. **Given** 在题库详情，**When** 新增单元 / 重命名 / 删除，**Then** 结果与网页端一致；单元下还有题时删除被服务端拒绝并显示原因。
3. **Given** 新增一道选择题，**When** 不填选项或没选正确答案，**Then** 本地就拦下并提示；填好后保存成功并出现在列表里。
4. **Given** 编辑一道简答题，**When** 只改参考答案并保存，**Then** 原来的评分要点不被清空。
5. **Given** 一道已上架的题，**When** 点「下架」，**Then** 列表状态变为已下架，且刷题时不再出现。
6. **Given** 要删掉整个题库，**When** 点「删除题库」，**Then** 必须先发邮箱验证码并填入正确验证码才能删除，删完回到题库列表。

**Why this priority**：题库维护是低频但刚需的动作，没有它，用户在手机上刷到错题只能等到回电脑再改。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 安卓端 MUST 只实现网页端已有的能力与业务规则（同一字段、同一状态、同一判定口径），
  MUST NOT 为安卓端单独设计业务规则或"仅 App 生效"的差异。
- **FR-002**: 安卓端 MUST 复用既有 `/api/**` 与同一套认证；MUST NOT 新增后端接口、平行路由或
  仅服务 App 的返回分支。本功能 MUST NOT 产生任何后端接口变更。
- **FR-003**: 会话 MUST 复用网页端同一套 JWT（登录下发的会话凭据）。凭据 MUST 只存于应用私有存储，
  MUST NOT 出现在日志、MUST NOT 随崩溃上报外泄。
- **FR-004**: 写请求 MUST 携带与网页端相同的安全校验头，否则后端按设计返回 403。
- **FR-005**: 登录 MUST 与网页端一致地要求图形验证码；注册与找回密码 MUST 使用邮箱验证码，
  发送频率限制（60 秒冷却）MUST 与网页端一致。
- **FR-006**: 判分 MUST 与网页端一致：选择题在客户端即时判定；简答/伪代码走服务端 AI 判分；
  AI 解析 MUST 复用服务端按题目缓存的解析，重复查看不重复扣点。
- **FR-007**: 做题进度 MUST 与服务端保持一致，退出应用后再次进入 MUST 能从上次未答的题目继续。
- **FR-008**: 未登录用户可以浏览公共题库列表；使用刷题、错题本、统计、点数等能力前 MUST 引导登录。
- **FR-009**: 所有错误提示 MUST 使用服务端返回的提示文案，MUST NOT 由客户端编造或改写语义。
- **FR-010**: 收到 401 MUST 回到登录页并说明原因；MUST NOT 静默失败。
- **FR-011**: 界面术语 MUST 与网页端统一（题库 / 单元 / 题目 / 解析 / 错题本 / 点数 / 套餐）。
- **FR-012**: 购买点数 MUST 引导到与网页端相同的支付入口（系统浏览器打开），
  安卓端 MUST NOT 内嵌支付表单、MUST NOT 保存任何支付凭据。
- **FR-013**: 题目正文与解析 MUST NOT 持久化到设备本地（仅在内存中展示），
  MUST NOT 因本地缓存造成私有题库内容残留。
- **FR-014**: 应用 MUST 在无模拟器可用时也能产出可安装的调试包，便于在真机验收。

### Key Entities

- **账号（Profile）**：邮箱、昵称、角色（普通用户 / 管理员）、状态、会话版本。
- **题库（Bank）**：名称、描述、是否公共（公共题库不属于任何账号）。
- **单元（Unit）**：所属题库、名称、排序、题目数。
- **题目（Question）**：题型（单选 / 多选 / 简答）、题干、选项、答案、解析、难度、状态（上架 / 下架）。
- **作答记录（PracticeRecord）**：所属账号与题目、作答内容、是否正确、得分、耗时。
- **错题（WrongBook 项）**：题目 + 答错次数。
- **点数账（Point Ledger）**：余额、变动原因、变动时间。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 已登录用户从打开应用到提交一道选择题，用时不超过 60 秒。
- **SC-002**: 冷启动到可交互不超过 3 秒（4G 网络、中端机型）。
- **SC-003**: P1 的四条主干（登录、刷题、续做、错题本）在真机上逐条走通，且与网页端结果逐项一致。
- **SC-004**: 同一账号、同一道题，安卓端与网页端的判定结果（对错、得分、解析来源）完全一致。
- **SC-005**: 调试安装包体积不超过 20 MB。
- **SC-006**: 本次改造后端接口变更为 0 条（可由后端测试与接口清单核对）。

## Assumptions

- 应用名「拾题」，包名 `site.seaunit.shuati`，默认中文界面。
- 最低支持 Android 8.0（minSdk 26），目标 API 36（本机可用的 SDK 平台为 android-36/37）。
- 购买点数跳系统浏览器完成，安卓端不内嵌支付；支付成功后的权益变化由服务端与网页端共同保证。
- 应用主色与网页端保持一致（白纸黑字 + moss 绿），不做另一套视觉体系。
- 本机没有可用的模拟器镜像：P1 的自动化验证以 JVM 单元测试 + 调试包构建为准，
  端到端四条主干由真机安装验收。
- 推送通知、离线题库、后台下载题库不在本期范围。
