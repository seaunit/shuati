# Feature Specification: 刷题入口恢复上次练习范围

**Feature Branch**: `013-practice-scope-resume`

**Created**: 2026-10-26

**Status**: Implemented

**Input**: 用户反馈 —— 「这个刷题模块没有按照上次刷题进度来，比如我上次刷的是八股100题，
点击刷题栏确是软考题」。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从侧栏继续上次题库 (Priority: P1)

用户上次在某个题库或单元里练习，离开刷题页后再次点击侧栏「刷题」，
系统应进入该题库或单元，并继续上次停留的题号，而不是打开所有题目的合集。

**Why this priority**: 练习范围错误会让用户看到的题数、已完成数和题号全部偏离预期，
是继续练习主流程的阻断问题。

**Independent Test**: 准备一条较新的「全部题目」记录和一条较旧但有效的题库记录，
从裸刷题入口进入；断言页面加载该题库，并落到该题库保存的题号。

**Acceptance Scenarios**:

1. **Given** 用户最近在题库 A 练习，**When** 点击侧栏「刷题」，
   **Then** 进入题库 A 并恢复到题库 A 的当前题。
2. **Given** 用户最近在单元 B 练习，**When** 点击侧栏「刷题」，
   **Then** 进入单元 B 并恢复到单元 B 的当前题。
3. **Given** 后续产生了「全部题目」或「错题重练」记录，**When** 用户再次点击「刷题」，
   **Then** 仍优先恢复到最近一次有效的题库/单元练习。
4. **Given** 用户从首页题目卡片、SEO 页面或错题本进入带明确范围的练习，
   **When** 页面加载，**Then** 必须尊重该明确范围，不得被最近练习范围覆盖。

### Edge Cases

- 用户从未在题库或单元中练习过：裸入口保持原行为，进入全部题目。
- 保存的题库或单元已被删除或当前账号无权访问：不得进入失效范围；回退到全部题目。
- 最近练习范围读取失败或超时：不得阻断刷题，回退到全部题目。
- 同一账号在 Web 与 Android App 使用：两端恢复同一练习范围与题号。
- 游客访问裸入口：仍先要求登录，不读取其他账号数据。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 裸刷题入口 MUST 优先恢复当前账号最近一次有效的题库或单元练习范围。
- **FR-002**: 恢复范围后 MUST 继续复用该范围的现有题号进度，不得重置为第 1 题。
- **FR-003**: 系统 MUST NOT 把「全部题目」或「错题重练」当作侧栏入口要恢复的长期范围。
- **FR-004**: 带有明确题库、单元或错题题集参数的入口 MUST 保持原参数，不被自动恢复覆盖。
- **FR-005**: 最近范围不存在、已失效、无权访问或读取失败时 MUST 回退到全部题目，页面不得报错。
- **FR-006**: 恢复逻辑 MUST 使用账号级服务端数据，确保 Web 与 App 一致。
- **FR-007**: 查询最近范围 MUST 继续执行题库可见性校验，不得暴露其他账号的私有题库信息。

### Key Entities

- **练习记录**：账号、练习范围类型、范围 id、开始时间；用于找出最近一次题库或单元练习。
- **练习光标**：账号和练习范围对应的当前题号；范围恢复后继续使用。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户描述的「上次八股 100 题，点击刷题却进入软考 422 题」流程在回归测试中不再出现。
- **SC-002**: 自动化测试覆盖题库恢复、单元恢复、旧 `ALL` 记录不抢占、显式入口不被覆盖、
  无历史与失效范围回退。
- **SC-003**: Web 与 Android App 通过同一页面与接口恢复相同范围，不新增仅客户端逻辑。
- **SC-004**: 既有练习、错题重练、题库权限与题号进度测试全部通过。

## Assumptions

- 最近一次有效题库/单元以服务端练习记录的开始时间为准。
- 「全部题目」和「错题重练」属于临时练习，不进入长期恢复范围。
- 明确带参数的练习链接优先于自动恢复。
