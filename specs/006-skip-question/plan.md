# Implementation Plan: 未作答也能跳过

**Branch**: `006-skip-question` | **Date**: 2026-10-17 | **Spec**: [spec.md](./spec.md)

## 技术方案

只改 `frontend/src/views/PracticeView.vue` 底部操作条：

- 「下一题 / 完成练习」不再依赖 `result`，始终可见可点；
- 未提交时操作条右侧同时给出「下一题」（次要按钮）与「提交答案」（主按钮），
  左侧仍是「上一题」；手机上三个按钮一行放得下（宽度已按 390px 校验）；
- 跳题复用现有的 `next()`：它只做 `index += 1` + `resetState()`，
  **不发提交请求**，所以跳过天然 0 分、不进错题本；
- 进度：`index` 变化会触发 `watch(index)` → 写练习光标（spec 004），跳过也记位置；
- 最后一道题的「完成练习」仍走 `finish()`：有未作答题时先 `confirm`，避免误跳过直接交卷。

## 影响面

| 位置 | 变更 | 风险 |
| --- | --- | --- |
| `PracticeView.vue` | 操作条按钮显隐与顺序 | 低：不动提交/判分/计分逻辑 |
| 后端 / DB | 无 | 无 |

## 测试策略

- Playwright 新增：未作答点「下一题」→ 到下一题；期间没有 `/api/practice/submit-*` 请求；
  写回的光标是新的当前题。
- 跑全量 `npx playwright test` 与 `npm run build` 确认无回归。

## 风险与回滚

- 风险：误点「下一题」跳过导致漏答。对策：交卷时对未作答题确认（已有），
  且跳过的题保持未作答、可随时点回去补答。
- 回滚：删掉「下一题」在未提交时的显隐条件即回到旧行为。
