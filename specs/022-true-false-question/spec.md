# Feature Specification: 判断题题型

**Feature Branch**: `test`

**Created**: 2026-10-28

**Status**: Ready

**Input**: User description: "新增一个题型类型判断题（正确/错误），先实现本地测试环境。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 练习判断题 (Priority: P1)

用户在练习页遇到判断题时，只看到“正确”和“错误”两个选项；选择并提交后立即得到本地判分和颜色反馈。

**Why this priority**: 这是新题型最核心的用户价值，必须先能可靠作答和判分。

**Independent Test**: 创建一道判断题，分别选择正确答案和错误答案提交，确认得分、判定、选项颜色和进度均正确。

**Acceptance Scenarios**:

1. **Given** 当前题目是判断题，**When** 用户打开练习页，**Then** 题型显示为“判断题”，并且只有“正确”“错误”两个选项。
2. **Given** 正确答案是“正确”，**When** 用户选择“正确”并提交，**Then** 判定为正确、得分为 10，正确选项显示绿色。
3. **Given** 正确答案是“错误”，**When** 用户选择“正确”并提交，**Then** 判定为错误、得分为 0，用户选择显示红色且正确答案显示绿色。
4. **Given** 用户开启背题模式，**When** 查看判断题，**Then** 正确选项直接高亮，答案文字显示“正确”或“错误”而不是内部编码。
5. **Given** 用户提交判断题，**When** 返回错题本或查看已答进度，**Then** 该题与其他题型使用同一套进度和错题规则。

---

### User Story 2 - 维护判断题 (Priority: P2)

有题库维护权限的用户可以新增和编辑判断题，只需选择“正确”或“错误”作为答案，不需要手工填写选项 JSON。

**Why this priority**: 没有可靠的内容维护入口，用户无法持续创建判断题。

**Independent Test**: 在自建题库新增一道判断题，再编辑答案并保存，重新打开表单确认内容正确回显。

**Acceptance Scenarios**:

1. **Given** 用户有题库维护权限，**When** 在新增题目中选择“判断”，**Then** 表单显示固定的“正确/错误”答案选择，不显示自定义选项编辑器。
2. **Given** 用户没有选择判断题答案，**When** 提交表单，**Then** 页面提示必须选择正确或错误。
3. **Given** 用户创建判断题时选择“错误”，**When** 保存成功，**Then** 题目只包含“正确”“错误”两个固定选项，标准答案为“错误”。
4. **Given** 用户编辑已有判断题并改成正确答案，**When** 再次打开编辑弹窗，**Then** 表单回显最新答案和题干。
5. **Given** 普通用户维护自己的题库，**When** 新增或编辑判断题，**Then** 权限规则与其他题型一致；普通用户仍不能修改他人或公共题库。

---

### User Story 3 - 导入、导出与展示判断题 (Priority: P3)

用户导入包含判断题的资料时，系统能识别并保存为判断题；Word 导出、错题本和公共页面也能正确显示题型。

**Why this priority**: 判断题需要贯穿现有内容生产与展示链路，避免导入后变成普通单选题。

**Independent Test**: 导入一段含“正确/错误”“对/错”或“√/×”的资料，确认生成判断题；导出 Word 后回读，确认题型和答案正确。

**Acceptance Scenarios**:

1. **Given** 资料中的问题明确要求判断正误，**When** AI 解析资料，**Then** 题型输出为判断题，选项固定为“正确/错误”，答案为二选一。
2. **Given** 导入结果里的答案写成“对”“错”“√”“×”“正确”或“错误”，**When** 保存到题库，**Then** 系统统一转换为标准答案。
3. **Given** 题库包含判断题，**When** 用户导出 Word，**Then** 文档显示“判断题”“正确/错误”选项和标准答案。
4. **Given** 公共题库包含判断题，**When** 用户在公开页面查看，**Then** 题型标签和答案显示为“判断题”和“正确/错误”。

### Edge Cases

- 判断题答案为空、同时包含两个答案或使用无效值时必须拒绝保存。
- 判断题选项缺失或选项顺序错误时，系统必须归一化为固定的“正确/错误”两项。
- 编辑题目时从单选/多选切换为判断题，必须清理旧选项并写入固定判断题选项。
- 编辑题目时从判断题切换为单选/多选，必须重新填写有效选项和答案。
- 判断题属于本地即时判分，不得调用 AI 判题，也不得产生 AI 判题点数流水。
- 历史题目的答案文本中只有“正确/错误”时必须仍可被归一化识别。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 增加独立题型 `TRUE_FALSE`，用户界面名称为“判断题”。
- **FR-002**: 判断题 MUST 固定使用两个业务选项“正确”和“错误”，不接受任意自定义选项。
- **FR-003**: 判断题标准答案 MUST 只能是“正确”或“错误”二选一。
- **FR-004**: 练习页 MUST 使用“正确/错误”展示判断题，不得向用户暴露内部编码。
- **FR-005**: 判断题提交 MUST 使用本地即时判分，答对得 10 分、答错得 0 分。
- **FR-006**: 作答后 MUST 用绿色标记正确选项；用户选错时 MUST 用红色标记其错误选择。
- **FR-007**: 背题模式、练习进度、错题本和错题重练 MUST 支持判断题。
- **FR-008**: 题库维护与后台管理表单 MUST 提供判断题类型和“正确/错误”答案选择。
- **FR-009**: 后端 MUST 对判断题选项、答案和题型执行服务端校验，不能只依赖前端。
- **FR-010**: 导入解析 MUST 能识别明确的正误判断题目，并将对/错、√/×、正确/错误等答案归一化。
- **FR-011**: Word 导出、错题本、公开题库和题目标签 MUST 正确显示“判断题”。
- **FR-012**: 网页端与 Capacitor 移动端 MUST 复用同一题型实现和既有接口，不得增加 App 专属接口或字段。
- **FR-013**: 现有单选、多选、简答题的行为 MUST 保持不变。

### Key Entities

- **Question**：题目，新增题型 `TRUE_FALSE`；判断题固定两个选项和单一标准答案。
- **PracticeRecord**：作答记录，判断题继续使用本地判分结果、分数和用户答案。
- **ImportItem**：AI 导入结果，判断题的答案和选项在入库前归一化。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可以从看到判断题到完成提交，使用不超过 3 次操作。
- **SC-002**: 判断题答对和答错的判定、10/0 分结果 100% 符合标准答案。
- **SC-003**: 判断题在练习页、背题模式、错题本和 Word 导出中 100% 显示为“判断题”。
- **SC-004**: 常见正误答案表达（对/错、√/×、正确/错误）100% 能归一化为标准判断答案。
- **SC-005**: 自动化测试覆盖创建、编辑、作答正确、作答错误、导入、导出和权限回归。

## Assumptions

- 判断题与单选题一样属于本地判分，不新增 AI 用途或点数规则。
- 判断题使用既有题库、单元、练习会话和错题本，不新增独立数据表。
- 本期只部署和验收本地测试环境，正式环境在验收通过后另行发布。
- 移动端继续使用同一份 Vue 前端产物，因此不单独修改原生壳。
