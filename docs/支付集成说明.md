# Waffo Pancake 支付集成说明

> SDK：`@waffo/pancake-ts@0.25.0`（RSA-SHA256 自动签名，零运行时依赖）
> 官方指南：https://docs.waffo.ai/zh/integrate/skill

## 1. 为什么需要 Node 侧车

本项目后端是 **Spring Boot（Java）**，而 `@waffo/pancake-ts` 是 **Node/TypeScript SDK**，
Java 无法直接调用。官方指南同时定了两条红线：

1. **私钥绝不能下发到浏览器** —— 所以不能放在 Vue 前端；
2. **绝不要自己手写 RSA-SHA256 签名** —— 所以不能在 Java 里重新实现一遍协议。

因此架构是：**Node 支付侧车持有私钥并签名，Java 只通过内网共享密钥与它通信**。

```
Vue ──下单──▶ Java(/api/orders) ──内网+共享密钥──▶ Node 侧车(/checkout) ──▶ Waffo API
                     ▲                                                          │
                     └──── 结算订单 ◀──(转发)── Node 侧车(/webhooks/waffo) ◀── 支付回调
```

## 2. 文件

```
payments/                          Node 支付侧车（独立进程）
  src/server.mjs                   HTTP 服务：/health、/checkout、/webhooks/waffo
  src/waffo.mjs                    SDK 客户端 + 私钥解析 + 商品映射
  src/catalog.mjs                  本项目 9 个商品（6 个订阅 + 3 个点数包）
  scripts/setup-catalog.mjs        一键在 Waffo 创建商品并打印 Product ID 映射
  .env.example                     配置模板

backend/.../payment/
  PaymentGateway.java              Java 调侧车创建收银台
  WaffoPaymentController.java      接收侧车转发的支付回调，幂等结算订单

backend/.../db/migration/V6__order_checkout.sql   订单表加 checkout_url / provider_session_id
deploy/systemd/shuati-payments.service            侧车 systemd 单元
```

## 3. 配置

`payments/.env`（已 gitignore）：

```bash
WAFFO_MERCHANT_ID=MER_7PGKvFIiNnnwwEO5RsJLTR
# 二选一：PEM 原文（支持 \n 转义）或 base64（推荐 CI/CD）
WAFFO_PRIVATE_KEY_BASE64=<把 private.pem 做 base64>
WAFFO_ENV=test
WAFFO_STORE_ID=STO_06yfSw5FByRGGzjlMVXC1n

# 商品映射：itemCode=ProductID，逗号分隔
WAFFO_PRODUCT_MAP=PLAN:plus:MONTHLY=PROD_xxx,PACK:pack_9=PROD_yyy

PORT=8090
JAVA_BASE_URL=http://127.0.0.1:8080
INTERNAL_SECRET=<随机值，Java 侧要配成同一个>
WAFFO_DRY_RUN=false
```

生成 base64：`cat private.pem | base64 | tr -d '\n'`（Windows 用 `certutil -encode`）。

Java 侧（`/etc/shuati/env`）：

```bash
SHUATI_PAYMENTS_ENABLED=true
SHUATI_PAYMENTS_URL=http://127.0.0.1:8090
SHUATI_PAYMENTS_SECRET=<与 INTERNAL_SECRET 相同>
SHUATI_PAYMENTS_CURRENCY=USD
```

## 4. 首次接入步骤

1. `npm --prefix payments install`
2. 复制 `payments/.env.example` 为 `payments/.env`，填入 `WAFFO_PRIVATE_KEY_BASE64` 和 `INTERNAL_SECRET`
3. 创建商品并拿到 Product ID：`npm --prefix payments run setup`
   —— 脚本会逐个创建 9 个商品并打印一行可直接粘贴的 `WAFFO_PRODUCT_MAP`
   （重复运行遇到同名商品会返回 409，跳过，去后台复制已有 ID 即可）
4. 把打印出的 `WAFFO_PRODUCT_MAP` 填回 `payments/.env`
5. 启动侧车：`npm --prefix payments start`
6. 启动 Java 并把 `SHUATI_PAYMENTS_ENABLED=true`，下单时就会返回 `checkoutUrl`

## 5. 支付流程

1. 用户点「选择该套餐 / 加量包」→ 前端 `POST /api/orders`
2. Java 建 `subscription_order`（PENDING）→ 调侧车 `POST /checkout`
3. 侧车用 SDK 创建 authenticated 收银台，把 `orderMerchantExternalId=订单号`、
   `metadata.orderId=订单号` 一起提交，返回 `checkoutUrl`
4. Java 把 `checkout_url` / `provider_session_id` 回写订单，接口把 `checkoutUrl` 返回前端
5. 前端 `window.open(checkoutUrl, "_blank", "noopener,noreferrer")`（官方建议新标签页打开）
6. 支付成功后 Waffo 回调 `POST /pay/webhooks/waffo`
7. 侧车用内置公钥 `verifyWebhook(rawBody, signature)` 验签，取出 `orderId`，
   带共享密钥转发给 Java `POST /api/payments/waffo/notify`
8. Java 只对 `order.completed` / `subscription.activated` / `subscription.payment_succeeded`
   发货，调用 `settleOrder(orderId, "PAID", true)` —— **幂等**，重复投递不会重复发点数

## 6. 本地联调

1. 用 `WAFFO_DRY_RUN=true` 可以先跑通「下单 → 拿到 URL」这条链路，不触碰真实 API
2. Webhook 需要公网可访问，用 **ngrok**（官方明确说 localtunnel 会丢自定义头）：

```bash
ngrok http 8080
# 把 https://xxx.ngrok-free.app/pay/webhooks/waffo 配到 Waffo 后台
```

3. 注册回调地址（也支持用 SDK 注册，见官方文档）：

```typescript
await client.webhooks.add({
  storeId, channel: "http", url: "https://你的域名/pay/webhooks/waffo",
  events: ["order.completed", "subscription.activated", "subscription.payment_succeeded"],
  testMode: true,
});
```

4. 测试卡（任意未来有效期、任意 CVC）：
   - 成功：`4576 7500 0000 0110`
   - 失败：`4576 7500 0000 0220`

## 7. 上线注意

- **换生产私钥**：测试和生产必须用不同的 API Key / 私钥，`WAFFO_ENV=prod`
- **`.publish()`**：测试环境创建的商品要发布到生产，否则生产收银台拿不到
- **Webhook 注册两份**：`testMode: true` 和 `testMode: false` 各一条
- **HTTPS**：回调地址必须 https，Nginx 已加 `/pay/webhooks/` 反向代理
- **金额口径**：本项目按「元」下发 `priceSnapshot`（`BigDecimal.valueOf(amountCents, 2)`），
  币种由 `SHUATI_PAYMENTS_CURRENCY` 决定；官方约定金额一律用展示金额字符串（`"19.00"`），
  **不要混用分**

## 8. 安全说明

| 项 | 做法 |
| --- | --- |
| 私钥 | 只在 Node 侧车内存中使用；不入库、不下发前端、不写日志 |
| 侧车鉴权 | `/checkout` 必须带 `X-Internal-Secret`，只有 Java 能调 |
| 回调鉴权 | 用 SDK 内置公钥验 RSA-SHA256 签名，验签失败直接 401 |
| 回调防重放 | SDK 默认 5 分钟时间窗 |
| 幂等 | Java 侧 `settleOrder(..., idempotent=true)`，重复事件不会重复发货 |
| 网络暴露 | Nginx 只暴露 `/pay/webhooks/`，`/checkout` 仅内网可达 |
| 回退 | 收银台创建失败不影响下单，订单仍为 PENDING，管理员可人工结算 |

## 9. 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 下单返回 `checkoutError: 未配置商品映射` | `WAFFO_PRODUCT_MAP` 没填或 itemCode 不匹配 |
| 回调一直 401 | 用了 localtunnel 导致签名头丢失，换 ngrok |
| 回调 500 且 Waffo 重试 | Java 侧结算失败（例如数据库不可用），查 Java 日志；重试是预期的 |
| 生产收银台打不开 | 商品只建在测试环境，需要 `.publish()` |
| 订单已支付但没发点数 | 检查事件类型是否在发货白名单内，以及 Java 日志里的结算记录 |
